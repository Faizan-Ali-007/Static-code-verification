# Code Review Report: game.cpp

| Line Number | Defect Type | Why It Is a Problem | Proposed Solution | Severity |
|---|---|---|---|---|
| 41 (triggered at 119) | Array / buffer overflow | `spawnMonster` has no bounds check. `main` spawns a 6th monster (Bat) but `MAX_MONSTERS` is 5, so it writes past the end of `monsters[]`, causing undefined behavior and memory corruption. | Check `if (monsterCount >= MAX_MONSTERS) return false;` before inserting and report failure to the caller, or use `std::vector<Monster*>`. | Critical |
| 47 | Logic error (assignment in condition) | `=` is used instead of `==`. This overwrites `monsters[i]->id` with the search id and always evaluates true (for nonzero id), so it returns the first monster and corrupts its data. | Change to `if (monsters[i]->id == id)`. | Critical |
| 54–58 (triggered at 123) | Null pointer dereference | `findMonster` can return `nullptr`, but `m->health` is used without a check. `main` calls `attackMonster(99, 20)` where no monster 99 exists, so the program crashes. | Add `if (m == nullptr) return -1;` right after `findMonster`. | Critical |
| 55–56 | Arithmetic / type error (signed-unsigned) | `damage` is converted to `unsigned int`, so `m->health - dmg` is unsigned and never `< 0`. The "already dead" check never works, and a negative damage becomes a huge number. | Keep the values signed: `if (damage < 0 \|\| m->health - damage < 0)`, and validate that `damage >= 0`. | High |
| 64 | Loop error (off-by-one) | `i <= monsterCount` reads one element past the last valid monster. `monsters[monsterCount]` is uninitialized or invalid, so dereferencing it is undefined behavior. | Change to `i < monsterCount`. | High |
| 70–73 | Dangling reference (return local variable) | Returns a reference to the local `label`, which is destroyed when the function returns. The caller then uses a dangling reference. | Return by value: `std::string getMonsterLabel(int id)`. | Critical |
| 71–72 | Null pointer dereference | `m` is used without checking whether `findMonster` returned `nullptr`. | Add `if (!m) return "Unknown";` before use. | High |
| 77 | Initialization error | `double sum;` is never initialized, so `sum +=` starts from a garbage value and the result is unpredictable. | Initialize with `double sum = 0.0;`. | High |
| 80 | Division by zero / implicit narrowing | If `monsterCount == 0`, this divides by zero. Also, the `double` result is silently truncated to `int`, losing precision. | Check `if (monsterCount == 0) return 0;` and change the return type to `double`. | Medium |
| 84–86 | Null pointer dereference | `m` from `findMonster` is not checked before `delete m` and `m->name`. | Add `if (!m) return;` after `findMonster`. | High |
| 85–86 | Use after free | `m->name` is accessed after `delete m`, which is undefined behavior. | Print the name first (or copy it into a local), then delete. | Critical |
| 85 (effect at 37) | Double delete / dangling pointer | After `delete m`, the pointer is still stored in `monsters[]` and `monsterCount` is unchanged. The destructor deletes it again, causing a double free. | Remove the entry from the array (shift the remaining elements, set the slot to `nullptr`) and decrement `monsterCount`. | Critical |
| 91 | Arithmetic error (integer division) | `attack * armorPercent / 100` is integer arithmetic, so `80 * 25 / 100` yields 20 and any fraction is lost before conversion to `double`. It may also overflow for large inputs. | Use `attack * armorPercent / 100.0` (or cast to `double` first). | Medium |
| 94–99 | Control flow error (missing return) | If `score <= 100`, no `return` is executed. `main` calls `playerRank(50)`, which is undefined behavior. | Add a final `else return 3;` (or a default return value). | High |
| 102 and 109 | Memory management error (`new[]` / `delete` mismatch) | Memory allocated with `new char[10]` must be freed with `delete[]`, not `delete`, which is undefined behavior. | Use `delete[] name;`, or better, use `std::string name;`. | High |
| 105 | Buffer overflow (unbounded input) | `std::cin >> name` into a 10-byte buffer has no length limit, so a name longer than 9 characters overflows the buffer. | Use `std::string name; std::cin >> name;`, or `std::cin >> std::setw(10) >> name;`. | Critical |
| 107 | Input validation / uninitialized variable | The result of `cin >> health` is not checked. On bad input `health` stays uninitialized (or 0) and is passed to `spawnMonster`. | Initialize `int health = 0;` and check `if (!(std::cin >> health))`; also validate the range. | Medium |
| 108 | Array / buffer overflow (capacity) | `readBoss` calls `spawnMonster` with no check that space remains in `monsters[]`. | Make `spawnMonster` return a status and check it here. | High |
| 121 | Memory leak | `bonus` is allocated with `new` and never deleted, and it is not used afterwards. | `delete bonus;` before `return`, or use `Monster bonus(0, "Slime", 1, 0);` or `std::unique_ptr`. | Medium |
| 133 | Shallow copy / double free (Rule of Three violation) | `Game` owns raw pointers but has no copy constructor or assignment operator. `Game copy = game;` copies the pointers, so both destructors delete the same monsters. | Implement a deep-copy constructor and `operator=` (Rule of Three/Five), delete them, or use `std::unique_ptr` / `std::vector<Monster>`. | Critical |
| 27–28, 31–33 | Initialization error | The `monsters[]` array pointers are never initialized, so unused slots hold garbage values. | Initialize in the constructor: `for (auto& p : monsters) p = nullptr;`. | Low |
| 130 | Logic error (repeated use of freed data) | `defeatMonster(3)` frees a monster that remains in `monsters[]`, so later calls like `totalMonsterHealth` use freed memory. | Fix `defeatMonster` as described for line 85 so removed monsters leave the array. | High |
